# Next.js

Используй этот skill при разработке и анализе Next.js-проектов.

## Основные правила

- Учитывай фактическую версию Next.js в `package.json`.
- При сомнениях в API или поведении Next.js используй Context7 и актуальную официальную документацию.
- Если проект использует App Router, придерживайся его стандартных возможностей и соглашений.
- По умолчанию предпочитай Server Components.
- Используй Client Components (`"use client"`) только когда действительно нужны состояние, обработчики событий, browser API или другие клиентские возможности.
- Не превращай всю страницу в Client Component из-за небольшого интерактивного участка — по возможности выделяй его в отдельный компонент.
- Для получения данных сначала рассматривай серверные возможности Next.js, а не `useEffect` + `fetch` в Client Component.
- Используй Route Handlers и Server Actions в соответствии с их назначением, не добавляя API-слой без необходимости.
- Используй стандартные возможности Next.js для маршрутизации, layouts, loading/error UI, metadata и изображений.
- Не используй устаревшие подходы из старых версий Next.js без проверки их актуальности.
- Не добавляй библиотеки, если задачу можно решить средствами Next.js, React или уже установленными зависимостями.
- Не усложняй архитектуру без необходимости.

## Данные и безопасность

- Серверную логику и доступ к базе данных выполняй на сервере.
- Никогда не передавай секреты и серверные credentials в клиентский код.
- Не доверяй данным, полученным от клиента.
- Проверяй авторизацию и права доступа на сервере.
- Валидируй пользовательские данные на сервере.
- При работе с датами явно учитывай разницу между календарной датой и временем с timezone.

## Типизация и React

- Используй TypeScript с точными и понятными типами.
- Избегай `any`, если можно корректно описать тип.
- Не создавай сложные типы и абстракции без необходимости.
- Не используй `useEffect`, `useMemo`, `useCallback` и `memo` без конкретной причины.
- Следуй существующей архитектуре и стилю проекта.

## Режим обучения

Пользователь изучает Next.js.

При реализации:
- объясняй важные решения, специфичные для Next.js;
- кратко объясняй новые концепции;
- если подход отличается от обычного React, объясняй почему;
- при наличии нескольких разумных решений кратко сравнивай их;
- предпочитай простые и понятные решения более сложным.

Не превращай каждый ответ в подробную лекцию — объясняй прежде всего то, что относится к текущей задаче.
